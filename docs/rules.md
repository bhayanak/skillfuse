# Rule catalogue

Generated by `make docs-rules`. Every rule carries a *confidence*:

- **deterministic**: a reproducible fact about the artefact (e.g. a zero-width character exists).
- **heuristic**: a pattern-based suspicion about intent (e.g. text that reads like an instruction override).

Policies treat them differently: by default only deterministic findings can *block*.

## Details

### SC-DEP-001

**Unpinned dependency install** — severity `medium`, confidence `deterministic`, category `dependency`

Installs a package without an exact version, so behaviour can change silently.

*Remediation:* Pin exact versions (and ideally hashes) or install from a lockfile.

- https://slsa.dev/spec/v1.0/requirements#dependencies

### SC-DEP-002

**Dependency installed from VCS or URL** — severity `high`, confidence `deterministic`, category `dependency`

Installing from git/http bypasses registry provenance and is usually unpinned.

*Remediation:* Install a published release pinned to a version and hash, or vendor the code.

### SC-DEP-003

**Repository cloned without a pinned revision** — severity `medium`, confidence `deterministic`, category `dependency`

`git clone` of a moving branch means the executed code can change at any time.

*Remediation:* Clone then `git checkout <commit-sha>`, or download a tagged archive and verify its digest.

### SC-DEP-004

**Custom package index or registry** — severity `medium`, confidence `deterministic`, category `dependency`

Redirects package resolution to a non-default index (dependency-confusion vector).

*Remediation:* Use the organisation-approved registry via configuration, not ad-hoc flags.

### SC-DEP-005

**Package-manager trust bypass** — severity `medium`, confidence `deterministic`, category `dependency`

Flags that disable integrity checks or install into the system interpreter.

*Remediation:* Remove the flag; use a virtual environment and keep integrity checks on.

### SC-EXF-001

**Credential file referenced** — severity `high`, confidence `deterministic`, category `exfiltration`

References well-known credential stores (AWS, SSH, kube, npm, .env, keychain, …).

*Remediation:* Skills should receive credentials via the host's secret mechanism, never by reading credential files.

### SC-EXF-002

**Environment variable harvesting** — severity `medium`, confidence `deterministic`, category `exfiltration`

Dumps or serialises the whole process environment, which typically contains tokens.

*Remediation:* Read only the specific variables you need.

### SC-EXF-003

**Hard-coded secret** — severity `high`, confidence `deterministic`, category `exfiltration`

Credential material committed inside the skill package.

*Remediation:* Remove the secret, rotate it, and source credentials from the host at runtime.

- https://cwe.mitre.org/data/definitions/798.html

### SC-EXF-004

**Outbound data transfer** — severity `medium`, confidence `deterministic`, category `exfiltration`

Sends request bodies or files to a remote endpoint.

*Remediation:* Declare `network.egress` and the destination hosts in the capability manifest.

### SC-EXF-005

**Credential read combined with outbound transfer** — severity `critical`, confidence `heuristic`, category `exfiltration`

The same file references credential material and performs outbound transfers — classic exfiltration shape.

*Remediation:* Separate credential handling from network code and justify both in the manifest.

### SC-EXF-006

**DNS/ICMP covert channel** — severity `high`, confidence `deterministic`, category `exfiltration`

Encodes data into DNS lookups or ping payloads to bypass HTTP egress controls.

*Remediation:* Remove the covert channel.

### SC-HID-001

**Invisible Unicode characters** — severity `critical`, confidence `deterministic`, category `hidden-content`

Zero-width or filler code points that can hide instructions from human reviewers.

*Remediation:* Strip the invisible characters; legitimate text almost never needs them.

- https://en.wikipedia.org/wiki/Zero-width_space

### SC-HID-002

**Bidirectional text override (Trojan Source)** — severity `high`, confidence `deterministic`, category `hidden-content`

Bidi control characters reorder how code/text is displayed versus how it is read.

*Remediation:* Remove bidi control characters (U+202A–U+202E, U+2066–U+2069).

- https://trojansource.codes/

### SC-HID-003

**Instruction-like HTML comment** — severity `medium`, confidence `deterministic`, category `hidden-content`

HTML comments are invisible in rendered Markdown yet fully visible to the model.

*Remediation:* Move instructions out of comments or delete them; reviewers must see what the model sees.

### SC-HID-004

**Large encoded blob** — severity `medium`, confidence `deterministic`, category `hidden-content`

Long base64/hex sequences can hide commands or payloads from review.

*Remediation:* Replace encoded payloads with plain, reviewable text or fetch pinned artefacts by digest.

### SC-HID-005

**Mixed-script confusable characters** — severity `medium`, confidence `deterministic`, category `hidden-content`

Words mixing Latin with Cyrillic/Greek look-alikes (e.g. 'сurl') evade simple pattern checks.

*Remediation:* Normalise to a single script; mixed scripts inside one word are almost always deceptive.

### SC-HID-006

**Visually hidden HTML content** — severity `high`, confidence `deterministic`, category `hidden-content`

HTML that renders invisible (display:none, zero font, white-on-white, collapsed details).

*Remediation:* Remove hidden HTML; content for the model must be visible to the reviewer.

### SC-HID-007

**Off-screen text after excessive whitespace** — severity `low`, confidence `deterministic`, category `hidden-content`

Hundreds of spaces push instructions beyond the visible editor width.

*Remediation:* Remove padding whitespace so every instruction is visible without horizontal scrolling.

### SC-META-001

**Missing name or description** — severity `low`, confidence `deterministic`, category `metadata`

Skills without a name/description cannot be reasoned about by policy or by the host.

*Remediation:* Add `name` and `description` to the frontmatter.

### SC-META-002

**Symlink points outside the package** — severity `high`, confidence `deterministic`, category `metadata`

A symlink that escapes the package root can read or write arbitrary host files.

*Remediation:* Replace the symlink with a copy of the intended file.

### SC-META-003

**Binary or executable artefact bundled** — severity `medium`, confidence `deterministic`, category `metadata`

Opaque binaries cannot be reviewed; executables inside skills are a common dropper pattern.

*Remediation:* Ship source instead of binaries; if unavoidable, publish checksums and a provenance attestation.

### SC-META-004

**Unusually large skill package** — severity `info`, confidence `deterministic`, category `metadata`

Large packages hide payloads and slow review.

*Remediation:* Keep skills small; move datasets and tooling into pinned external artefacts.

### SC-META-005

**Suspicious file placement** — severity `low`, confidence `deterministic`, category `metadata`

Files that masquerade as something else or are hidden in dot-directories.

*Remediation:* Keep all package content in visible, descriptively named files.

### SC-NET-001

**Plaintext (non-TLS) URL** — severity `low`, confidence `deterministic`, category `network`

Plaintext (non-TLS) URL

*Remediation:* Use https:// so content cannot be tampered with in transit.

### SC-NET-002

**Raw IP address endpoint** — severity `medium`, confidence `deterministic`, category `network`

Raw IP address endpoint

*Remediation:* Use a named host with TLS; raw IPs evade allowlists and TLS validation.

### SC-NET-003

**Shortener, paste site, tunnel, or OAST endpoint** — severity `high`, confidence `deterministic`, category `network`

Shortener, paste site, tunnel, or OAST endpoint

*Remediation:* Link to the canonical, reviewable source instead.

### SC-NET-004

**Suspicious top-level domain** — severity `low`, confidence `deterministic`, category `network`

Suspicious top-level domain

*Remediation:* Verify the destination is legitimate; prefer well-known domains.

### SC-NET-005

**Domain outside the configured allowlist** — severity `medium`, confidence `deterministic`, category `network`

Domain outside the configured allowlist

*Remediation:* Add the domain to `network.allowed_domains` if it is expected.

### SC-NET-006

**Internationalised (punycode) domain** — severity `medium`, confidence `deterministic`, category `network`

Internationalised (punycode) domain

*Remediation:* Punycode domains are a common homograph phishing vector; verify intent.

### SC-NET-007

**Credentials embedded in URL** — severity `high`, confidence `deterministic`, category `network`

Credentials embedded in URL

*Remediation:* Never embed credentials in URLs; pass them via headers from a secret store.

### SC-NET-008

**Non-standard port** — severity `low`, confidence `deterministic`, category `network`

Non-standard port

*Remediation:* Confirm why a non-standard port is required.

### SC-PI-001

**Instruction override attempt** — severity `high`, confidence `heuristic`, category `prompt-injection`

Text that tells the model to ignore, forget, or override prior/system instructions.

*Remediation:* Remove language that overrides the host's system prompt or the user's prior instructions.

- https://owasp.org/www-project-top-10-for-large-language-model-applications/

### SC-PI-002

**Concealment directive** — severity `high`, confidence `heuristic`, category `prompt-injection`

Instructs the model to hide actions, output, or this instruction from the user.

*Remediation:* Skills must be transparent: never instruct an agent to hide behaviour from the user.

### SC-PI-003

**Role or identity hijack** — severity `medium`, confidence `heuristic`, category `prompt-injection`

Jailbreak-style persona switching or 'developer mode' framing.

*Remediation:* Describe the task; do not redefine the assistant's identity or claim to unlock hidden modes.

### SC-PI-004

**Instruction to exfiltrate context or secrets** — severity `critical`, confidence `heuristic`, category `prompt-injection`

Asks the model to send conversation context, system prompt, files, or credentials somewhere.

*Remediation:* Never instruct an agent to transmit environment variables, credentials, or prompt context.

### SC-PI-005

**Conditionally triggered behaviour** — severity `medium`, confidence `heuristic`, category `prompt-injection`

Behaviour that activates only for specific users, dates, counts, or environments (logic-bomb style).

*Remediation:* Skills should behave identically for all users and environments; remove hidden triggers.

### SC-PI-006

**Approval or confirmation bypass** — severity `high`, confidence `heuristic`, category `prompt-injection`

Instructs the agent to skip user confirmation, auto-approve tool calls, or force destructive actions.

*Remediation:* Let the host's permission model govern tool execution; never pre-authorise on the user's behalf.

### SC-PI-007

**Unconditional tool-call coercion** — severity `medium`, confidence `heuristic`, category `prompt-injection`

Forces the model to always invoke a specific external tool or URL before/after every response.

*Remediation:* Invoke tools when the task requires them, not unconditionally on every turn.

### SC-PI-008

**Instructions sourced from a remote URL** — severity `high`, confidence `heuristic`, category `prompt-injection`

Tells the agent to fetch and follow instructions hosted elsewhere, defeating static review.

*Remediation:* Vendor instructions into the package so they are reviewable and hash-pinned.

### SC-SH-001

**Remote script piped to a shell** — severity `critical`, confidence `deterministic`, category `shell`

Downloads content and executes it without inspection or pinning.

*Remediation:* Download to a file, verify its digest/signature, then execute a pinned version.

- https://cwe.mitre.org/data/definitions/494.html

### SC-SH-002

**Destructive filesystem operation** — severity `critical`, confidence `deterministic`, category `shell`

Recursive deletes of broad paths, disk wipes, fork bombs.

*Remediation:* Scope deletes to files the skill created; never touch $HOME, /, or unquoted variables.

### SC-SH-003

**Privilege escalation or permissive modes** — severity `high`, confidence `deterministic`, category `shell`

sudo/su usage, world-writable or setuid permissions.

*Remediation:* Skills should not require elevated privileges; if unavoidable, declare `system.admin`.

### SC-SH-004

**Obfuscated command execution** — severity `critical`, confidence `deterministic`, category `shell`

Decodes or constructs code at runtime and executes it.

*Remediation:* Write commands in plain text so they can be reviewed.

### SC-SH-005

**Persistence mechanism** — severity `high`, confidence `deterministic`, category `shell`

Installs scheduled tasks, services, shell-rc hooks, SSH keys, or git hooks.

*Remediation:* Skills must not outlive the task; remove persistence.

### SC-SH-006

**Security control tampering** — severity `high`, confidence `deterministic`, category `shell`

Disables TLS verification, shell history, git hooks, firewalls, or scanners.

*Remediation:* Keep security controls enabled; fix the underlying problem instead.

### SC-SH-007

**Reverse or bind shell** — severity `critical`, confidence `deterministic`, category `shell`

Opens an interactive shell to/from a remote host.

*Remediation:* Remove immediately; this is never legitimate inside a skill.

### SC-SH-008

**Downloaded artefact made executable** — severity `high`, confidence `deterministic`, category `shell`

Fetches a binary/script and marks it executable (two-step pipe-to-shell).

*Remediation:* Verify a pinned checksum/signature before `chmod +x` and execution.

### SC-TOOL-001

**Over-broad tool grant** — severity `medium`, confidence `deterministic`, category `tool-overreach`

Agent/prompt grants all tools or an unusually large tool set.

*Remediation:* Enumerate the minimal tools the task needs.

### SC-TOOL-002

**Tools exceed stated purpose** — severity `high`, confidence `heuristic`, category `tool-overreach`

Description reads as read-only/analytical, yet write/exec/network tools are granted.

*Remediation:* Either narrow the tools or make the description honest about what the agent can do.

### SC-TOOL-003

**Secret literal in MCP server environment** — severity `high`, confidence `deterministic`, category `tool-overreach`

MCP server config embeds a token/password instead of referencing an input or environment variable.

*Remediation:* Use `${input:…}` / `${env:…}` references so secrets never live in the config file.

### SC-TOOL-004

**MCP server launched from an unpinned package** — severity `medium`, confidence `deterministic`, category `tool-overreach`

`npx -y pkg` / `uvx pkg` fetch and execute the latest published version at every start.

*Remediation:* Pin an exact version (`npx -y pkg@1.2.3`, `uvx pkg==1.2.3`) or install the server explicitly.

### SC-TOOL-005

**MCP server command from untrusted location** — severity `high`, confidence `deterministic`, category `tool-overreach`

Server binary lives in a temp dir, is fetched at launch, or is a bare shell with inline code.

*Remediation:* Launch servers from a reviewed, installed location.

### SC-TOOL-006

**Destructive tools granted without confirmation guidance** — severity `medium`, confidence `heuristic`, category `tool-overreach`

Agent grants delete/destructive/force tools but its instructions never mention confirming with the user.

*Remediation:* Add explicit 'ask before destructive actions' guidance or drop the tools.

### SC-TOOL-007

**Lifecycle hook executes commands** — severity `medium`, confidence `deterministic`, category `tool-overreach`

Plugin/skill hooks run shell commands automatically on session or tool events.

*Remediation:* Hooks run without a prompt; keep them minimal, reviewed, and declared in the manifest.
